# 설치와 첫 검색

<Lead>

CLI, Rust와 npm 환경에 kfind를 설치하고 [표제어](/reference/glossary#lemma) 검색, [품사](/reference/glossary#part-of-speech) 지정, 자동화용 출력을 확인하는 최소 절차입니다.

</Lead>

## CLI 설치 [#cli-installation]

macOS와 Linux에서는 Homebrew formula가 CLI와 같은 릴리스의 형태 리소스를 함께 설치합니다. 소스 체크아웃에서는 Cargo로 설치할 수 있습니다.

```bash
brew install seokminhong/brew/kfind

# source checkout
cargo install --locked --path crates/kfind-cli

kfind --version
```

검색 중에는 네트워크를 사용하지 않습니다. Homebrew 설치본은 full [POS](/reference/glossary#part-of-speech) [형태 사전](/reference/glossary#lexicon), 용언 metadata와 [구성 요소 리소스](/reference/glossary#component-resource)를 formula 경로에서 찾습니다. 리소스 schema나 source digest가 실행 파일과 맞지 않으면 검색을 시작하지 않고 오류를 반환합니다.

## npm 설치 [#npm-installation]

JavaScript와 TypeScript에서는 `@kfind/kfind` 패키지를 설치합니다. 패키지는 WebAssembly 엔진과 기본 lexicon을 포함하며, 파일 시스템이나 URL을 임의로 읽지 않습니다.

```bash
npm install @kfind/kfind@1.0.1
```

```javascript
import { Kfind } from '@kfind/kfind';

const engine = new Kfind();
const plan = engine.compile('걷다', { pos: 'verb' });
const matches = plan.findAll('나는 길을 걸었다.');
```

Node.js 20 이상에서는 설치 없이 같은 패키지의 `kfind` 명령을 실행할 수 있습니다. `yarn dlx`는 Yarn 2 이상에서 사용합니다.

```bash
npx @kfind/kfind 걷다 README.md
pnpm dlx @kfind/kfind 걷다 README.md
yarn dlx @kfind/kfind 걷다 README.md
```

브라우저와 Node.js는 같은 [검색 질의](/reference/glossary#query) 컴파일과 메모리 내 텍스트 일치 규칙을 사용합니다. 전체 품사 사전이나 구성 요소 판정이 필요하면 패키지가 공개하는 asset을 읽어 byte 배열로 전달해야 합니다.

## 표제어 검색 [#first-search]

첫 번째 위치 인자는 검색 질의입니다. 이어지는 인자에는 검색할 파일이나 디렉터리를 지정합니다. 경로가 없으면 pipe 입력을, 대화형 터미널에서 stdin도 없으면 현재 디렉터리를 검색합니다.

```bash
kfind 걷다 src docs
kfind 사용자 .
printf '길을 걸었다.
' | kfind 걷다
```

`걷다`는 동사이자 ㄷ [불규칙 활용](/reference/glossary#irregular-conjugation) 표제어로 분석됩니다. [검색 계획](/reference/glossary#query-plan)은 `걷고`, `걷는`, `걸어` 같은 후보의 고정 [anchor](/reference/glossary#anchor)와 suffix 판정 조건을 만들고, 원문에서는 이 조건을 통과한 span만 반환합니다.

## 품사, 구와 대안 검색 [#pos-and-phrase]

사전 분석이 중의적이거나 입력의 문법 역할을 알고 있다면 `--pos`를 지정합니다. [구 검색](/reference/glossary#phrase)은 각 [atom](/reference/glossary#atom) 앞에 품사 태그를 붙입니다. 따옴표로 묶은 atom은 공백과 문장부호를 포함한 literal로 처리합니다. 여러 atom 중 하나를 찾으려면 `|`를 사용합니다.

```bash
kfind --pos verb 걷다 src
kfind 'v:걷다 | n:사용자 | n:검증' src
kfind 'n:사용자 v:검증하다' src
kfind 'det:새 n:기능' docs
kfind '"Hello, world!"' README.md
```

atom 태그는 `n:`, `pro:`, `num:`, `v:`, `adj:`, `det:`, `adv:`, `j:`, `intj:`, `lit:`을 지원합니다. 전역 품사와 atom 품사가 다르면 질의 컴파일 오류가 발생합니다. `|`가 있는 질의는 셸이 pipe로 해석하지 않도록 전체를 따옴표로 묶습니다. 각 대안은 하나의 atom이어야 하며 공백 구와 섞을 수 없습니다. Literal `|`는 `\|` 또는 `"|"`로 작성합니다.

## 자동화 출력 [#automation-output]

자동화에서는 품사, [경계 정책](/reference/glossary#boundary), 리소스와 출력 형식을 명시합니다. `any`는 부분 문자열 후보를 보존해 [재현율](/reference/glossary#recall)을 우선하고, JSON Lines는 원문 span과 [생성 근거](/reference/glossary#provenance)를 안정적으로 제공합니다.

```bash
kfind --embedded --boundary any --pos verb --json 걷다 src
kfind --embedded --boundary any --json 'n:사용자 v:검증하다' src
```

재현율을 우선한 결과에는 의미가 맞지 않는 후보도 포함될 수 있습니다. 호출자는 span 주변의 원문을 읽고 작업 목적에 맞는 결과인지 확인해야 합니다.

## 에이전트 통합 [#agent-skill]

`--init`은 지원하는 코딩 에이전트에 kfind skill과 project hook을 설치합니다. 검색 질의나 경로와 함께 사용할 수 없습니다.

```bash
kfind --init
kfind --init --agent codex --agent claude-code
kfind --uninstall --agent codex --agent claude-code
printf 'codex
gemini
' | kfind --init
```

Codex는 `.agents/skills/kfind/SKILL.md`, Claude Code는 `.claude/skills/kfind/SKILL.md`, Gemini CLI는 `.gemini/skills/kfind/SKILL.md`를 사용합니다. `--uninstall`은 kfind가 관리하는 skill과 hook만 제거합니다. 관리 표식이 없는 기존 skill과 에이전트 설정은 보존합니다. 프로젝트 hook을 신뢰하면 세션마다 모든 한국어 코드·문서 검색에 kfind를 사용하라는 지침을 받고, 한글 검색 패턴을 `rg`·`grep`에 전달하는 셸 명령은 실행 전에 차단됩니다.
