# 성능 측정

앵커 검색이 빠르다는 사실은 형태 검색 전체가 ripgrep과 같은 속도라는 뜻은 아닙니다. kfind는 질의 컴파일·리소스 초기화·후보 구조 검증 비용을 추가로 부담합니다. [검색 전략 비교](/benchmarks#search-strategy-baseline)에서는 실행 시간과 검색 품질을 함께 읽어야 합니다.

## Workload [#workloads]

Morphology는 fresh process initialization, cases/s, p95와 RSS를 측정합니다. 질의 컴파일, matcher 검색, 1 GiB 파일 검색, npm startup과 TUI index는 별도 entrypoint를 사용합니다.

정규식 기준선은 같은 단일 파일에 7개 질의를 각각 fresh process로 실행합니다. Batch wall time은 kfind, rg와 grep 조합별로 분리합니다.

Lock 대기와 빌드 시간은 workload 시간에서 제외합니다. 실행 환경과 binary revision에는 포함해 기록합니다.

## 통계 [#statistics]

형태 backend는 warm-up 1회 뒤 5회 측정합니다. 정규식 기준선은 warm-up 2회 뒤 10회 측정합니다. Median, min, max와 p95를 보고하며, 단발 실행이나 smoke test 성공은 성능 근거로 사용하지 않습니다.

Throughput, latency, seconds와 bytes를 같은 percent score로 합치지 않습니다.

## 회귀 판정 [#regression]

Baseline과 candidate는 같은 toolchain, 리소스, 입력 checksum과 옵션을 사용합니다. 품질 projection도 함께 실행해 빠르지만 잘못된 candidate를 채택하지 않습니다.

불리한 증감과 noise 범위를 모두 보고합니다. 원인을 확인하지 못했다면 추정이라고 표시합니다.
