# 한국어 활용형 검색 엔진, kfind

<Lead>

`걷다`를 검색해 `걷고`, `걸어`, `걸었다`까지 찾습니다. 파일과 소스 코드에서 한국어 [표제어](/reference/glossary#lemma)의 활용형을 모으고, 원문 위치와 생성 근거를 확인하는 도구입니다.

</Lead>

```bash
printf '길을 걸었다.\n' | kfind --pos verb 걷다
```

설치 없이 입력과 결과를 비교하려면 [플레이그라운드](/playground)를 사용합니다.

- [설치와 첫 검색](/guide/getting-started)에서 명령을 실행하고 결과를 읽습니다.
- [검색 예시](/cli/recipes)에서 코드 탐색과 문서 검색에 맞는 질의를 고릅니다.
- [결과 해석과 진단](/cli/diagnostics)에서 결과 없음, 오류와 검색 한계를 점검합니다.

## 사용 환경 [#usage-profiles]

파일·저장소 검색에는 ignore 규칙, 문맥 출력과 스트리밍 입력을 지원하는 네이티브 CLI를 사용합니다. Node.js의 npm 경량 CLI는 UTF-8 텍스트를 검색하며 탐색 규칙과 JSON 형식이 다릅니다. 두 설치 방식의 출력은 그대로 교환할 수 없습니다.

코딩 에이전트는 [검색 절차](/agents/workflow)를 따라 넓게 수집한 후보의 문맥을 확인합니다. 자동으로 지침과 hook을 등록하려면 [통합 설치의 동작과 해제](/agents/skills)를 먼저 확인합니다.

애플리케이션에서 문자열을 검색하려면 [JavaScript API](/reference/javascript) 또는 [Rust API](/reference/rust)를 사용합니다. [JSON Lines](/reference/jsonl)는 CLI 출력과 좌표계를 설명합니다.

## 검색 범위와 한계 [#grammar-scope]

명사와 조사 결합, 동사·형용사의 어미와 불규칙 활용, 품사를 지정한 순서형 구를 찾습니다.

**`걷다`와 `걸다`는 활용형 `걸어`가 겹칩니다.** 따라서 `걷다`를 검색하면 `길을 걸어`뿐 아니라 `전화를 걸어`도 후보가 됩니다. kfind는 같은 활용형이 문맥에서 어느 표제어의 뜻으로 쓰였는지 구분하지 않습니다. 검색 결과의 뜻은 사용자가 주변 문맥을 읽고 판단해야 합니다.

기본 `smart` 경계는 구조 근거로 불필요한 후보를 줄이지만, `전화를 걸어`처럼 형태적으로 가능한 후보의 의미까지 구분하지는 않습니다. `any`는 단어 내부 후보를 더 넓게 모읍니다. [경계 정책](/cli/boundaries)은 정밀도와 재현율의 선택이며, 오타 교정이나 완전한 회수 보장은 아닙니다.

지원하지 않는 형태와 구조 판정 한계 때문에 누락될 수 있습니다. [벤치마크](/benchmarks)의 표준문·오류 문장 결과를 따로 읽고, 실제로 검색할 문서에서도 확인해야 합니다.

## 검색 엔진 구조 [#search-directed-morphology]

kfind는 짧은 질의를 분석해 검색 계획을 만들고, 본문에서 고정 문자열을 찾은 다음 후보 주변만 검증합니다. 본문 전체를 형태소 분석하지 않습니다. [검색 파이프라인](/internals/pipeline)에서 컴파일·탐색·검증의 관계를 설명합니다.

전체 실행 비용에는 질의 분석, 사전 초기화와 구조 검증이 포함됩니다. [성능 측정](/benchmarks/performance)은 입력·설정·품질 조건별로 해석해야 하며, 고정 문자열 검색 속도만으로 전체 형태 검색 시간을 예측할 수는 없습니다.
