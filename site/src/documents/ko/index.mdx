# 한국어 [활용](/reference/glossary#inflection)형까지 찾는 검색 엔진, kfind

<Lead>

‘걷다’를 검색하면 ‘걷고’, ‘걸어’, ‘걸었다’까지 찾습니다. kfind는 한국어의 [조사](/reference/glossary#particle), [어미](/reference/glossary#ending), [불규칙 활용](/reference/glossary#irregular-conjugation)을 고려해 파일과 코드에서 원하는 [표제어](/reference/glossary#lemma)와 구를 검색하는 고성능 검색 엔진입니다.

</Lead>

## 제품 목적 [#product-purpose]

입력은 찾으려는 표제어, 선택적 [품사](/reference/glossary#part-of-speech)와 검색 옵션입니다. 출력은 원문 span과 그 span을 생성한 표제어·품사·규칙 경로입니다. 예를 들어 `걷다`는 `걷고`, `걸어`, `걸었다`의 후보를 만들고, 원문에서 실제 형태와 경계 판정을 통과한 위치만 반환합니다.

corpus 전체의 형태소열, 문장 구조나 단어 의미를 반환하는 제품은 아닙니다. 의미가 다른 `걸다`와 `걷다`가 같은 표면형을 만들 수 있으면 두 [생성 근거](/reference/glossary#provenance)를 보존합니다. 최종 의미 판별은 결과 주변 문맥을 아는 호출자가 수행합니다.

## 검색 중심 형태 처리 [#search-directed-morphology]

일반적인 형태소 분석기는 관찰한 문장을 입력으로 받아 각 token의 표제어와 품사를 추정합니다. kfind는 표제어와 품사를 먼저 받은 뒤, 검색 가능한 [anchor](/reference/glossary#anchor)와 허용되는 조사·어미·불규칙 교체를 계산합니다. 입력과 출력의 방향이 반대입니다.

이 모델에서는 형태 처리 비용이 큰 corpus가 아니라 짧은 [query](/reference/glossary#query)에 집중됩니다. Corpus에서는 고정 byte anchor를 먼저 찾고 그 주변만 Unicode 경계와 국소 형태 구조로 검증합니다. 전체 문장을 분석하지 않아도 활용형 [recall](/reference/glossary#recall), 파일 단위 streaming과 생성 근거를 한 검색 계약 안에서 제공할 수 있습니다.

## 한국어 문법 범위 [#grammar-scope]

체언은 복수 접미사와 조사 연쇄를 처리합니다. 조사는 받침 유무와 `ㄹ` 받침을 기준으로 `은/는`, `이/가`, `으로/로` 같은 [이형태](/reference/glossary#allomorph)를 고릅니다. 용언은 규칙 활용과 ㄷ·ㅂ·ㅅ·르·러·ㅎ 불규칙, 우·오 축약, [선어말어미](/reference/glossary#prefinal-ending)와 종결·연결·관형·명사형 어미 연쇄를 지원합니다.

지정사, 보조용언, [파생](/reference/glossary#derivation) 접미사와 합성용언 내부 성분은 compact [component resource](/reference/glossary#component-resource)가 token 안의 품사·span 연결을 증명할 때만 `smart` 후보로 유지합니다. 규칙 목록에 없는 임의 조합과 문맥 의미 추론은 생성하지 않습니다.

## 사용 경로 [#usage-profiles]

사람이 직접 검색할 때는 품사를 생략한 `auto`와 `smart` 경계가 기본입니다. Full [POS](/reference/glossary#part-of-speech) 사전과 국소 구조 근거를 사용해 token 내부 [오탐](/reference/glossary#false-positive)을 제한합니다.

에이전트는 각 [atom](/reference/glossary#atom)의 품사를 명시하고 `--embedded`, `--boundary any`, `--json`을 함께 사용합니다. 이 경로는 recall과 낮은 초기화 비용을 우선하며, 에이전트가 span 주변을 읽어 의미상 후보를 선택합니다. CLI, Rust와 npm WebAssembly API는 같은 [query plan](/reference/glossary#query-plan)과 provenance 구조를 공유합니다.
