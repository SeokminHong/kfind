# 장소 조사와 주제 보조사의 축약

`가운데선`은 `가운데서는`의 구어 축약이다. 기존 `에서+는 → 에선`
조사 전이와 같은 경로로 `서+는 → 선`을 확인한다. Smart에서 체언 근거를
검증하고, `해안선`처럼 독립 체언이거나 `나선`처럼 용언 활용이
성립하는 어절의 경계를 보존한다. [국립국어원 지역어 조사, 여기선과 여기서는의 대응](https://www.korean.go.kr/common/download.do?c_file_name=180cf280-6e36-4899-9f92-0a7cb53adf00.pdf&file_path=reportData&o_file_name=KR20120116.pdf)

## 정확한 반환 범위

고정 음성과 GSD 원문·등록 교정문에서 체언 후보 뒤에 `선`이 오는
어절을 조사했다. 어절 말미 18건과 내부 51건 가운데 `가운데선`의
범위만 [10, 19)에서 [10, 22)로 달라졌다. 같은 규칙으로 검토한
`대해선`에는 펼친 표기 `대해서`에 독립 용언 분석이 있다. 기존
`에선`과 분절이 겹치는 입력, `최전선`·`해안선`의 전체 및 가능한
체언 성분 반환은 유지됐다. 두 대조 입력 SHA-256은
`465549c5381301abf514a0777c0c136b52b1f42e8d5e8df0326d41c35de00739`와
`89bf9c2b8e992560e46fc7a0d08dad1f7af26d75550c6c130d8612fcad107b42`다.

원문 `제약사 가운데선 …`의 표기를 보존했다. 같은 57개 질의를
원문의 축약과 `제약사 가운데서는 …`에 적용했다. 축약에서
명사 `가운데`의 범위만 늘었고 풀어 쓴 표기의 [10, 25)는
양쪽에서 정확히 일치했다. 이 입력의 SHA-256은
`89ed48aa142c9a0241b522840db25a8c168880f7032a6bd4397aff0a82e25d52`다.
`도서관선` [0, 12), `여기선` [0, 9) 및 `해안선` 안의 명사 성분
`해안` [0, 6)도 정확 범위 회귀에 포함했다.

고정·등록 평가의 258,541개 반환과 원문 GSD 9,335행에서
`gsd:test-s575:2`의 Smart 범위만 달라졌다. Token과 Any의
반환은 모두 같았다. 등록 교정 GSD에 정확한 조사 범위를 기록하면
같은 기준선 FPc는 2 → 3, FNc는 0 → 1이다. 아래 표는 동일한
정답으로 채점한 제품 비교다.

## 네이티브 형태 판정

Apple M1 Max 32 GiB, macOS 26.6.2 arm64, Rust·Cargo 1.97.0,
Python 3.14.8에서 기준선 `aebe0e14`와 후보 `569a27de`를
release로 비교했다. 같은 입력과 리소스로 각 조건을 한 번 가동한 뒤
순서를 교대하며 새 프로세스로 5회 측정했다. 표는 중앙값 [최솟값,
최댓값]이며 p95는 실행별 최근접 순위다.
[입력·사전 체크섬](2026-11-23-native-nominal-prefix-examples.md#네이티브-형태-판정)

## WebAssembly

`wasm-pack build crates/kfind-wasm --target bundler --out-dir "$out" --out-name kfind --release`
와 wasm-pack 0.15.0에서 기본 WASM은 2,839,864 → 2,840,676바이트다.
`gzip -9nc`는 965,144 → 963,793바이트, `brotli -q 11 -c`는
710,871 → 710,713바이트다. Node 26.11.1에서 기본 API의 명시적 Smart
명사 검색이 component를 요구하는 것을 확인했다. 사전을 장착한 API는
canonical 모드의 NFC와 NFD에서 `가운데선`, `여기선`, `해안선`의
범위를 검증했고, `나선`에서 Any와 Token의 기존 범위도 확인했다.
