# 조사 내부의 용언 후보 판정

Smart는 체언과 조사 구조를 선택한 뒤, 첫 조사에 어간 전체가
포함되는 runtime 용언 분할을 제외한다. 사전에서 확인한 조사
성분과 기존 조사 verifier가 검증한 어절 끝까지의 조사 연쇄를
사용한다. `글에서`를 잘못 분할해 찾던 동사 `서다`와
`낮이나`의 동사 `나다`가 대상이다. `문 앞에 서 있었다`,
`땀이 난다`와 체언 `글에서`의 전체 반환 범위는 유지한다.

## 원문과 교정문

동사 `서다`의 고정 음성 280행과 원문·교정 GSD 양성 각
1행을 실행했다. 고정 음성에서 이 동사의 FPc 25행 중
4행의 장소 조사 내부 범위가 제거됐다. 3행은 전부 사라졌고,
해안에서가 등장한 1행에는 별개 오반환 `섬의` [80, 86)이
남았다. 남은 22행에는 `갖춰서` 등의 연결 어미, `나선` 등
합성 동사, `섬`과 명사 뒤 조사가 포함된다.

전체 비교에서 바뀐 6문장과 별도 교정문에서 확인된 1문장의
모든 고정 질의를 원문·교정문 각 330건으로 재실행했다.
입력 SHA-256은
`f8b0bab903e55ab5c7c5f30c2d2bec5438dfb9ba9ded80b663063372c5a61149`다.

`그때까지는`의 범위는 두 빌드가 이미 제외했다.
`자료를 보낼 때까지는`의 [23, 29)는 표준 띄어쓰기가 적용된
대조문에서 기준선이 반환했고 후보가 제외했다. `설명한 글에서`는
교정문에서 오반환이 나타났고 후보에서 제거됐다.
`해안에서 온 사람은 강가에 서서 먼저 보고 뒤로 섰다`에서
독립 동사의 두 범위 [37, 43), [65, 71)를 모두 보존했다.

## 네이티브 성능

Apple M1 Max, macOS 26.6.2 arm64, Rust 1.97.0, Python 3.14.8에서
기준선 `ef6fba64`과 후보 `752d1121`을 동일 리소스로 비교했다.
집중 입력은 고정 음성·원문 GSD·교정 GSD에서 각각 `서다`,
`나다`, `지다` 질의를 추출해 원래 순서대로 연결한 858건이다.
입력 SHA-256은
`ffb18e8bd74b3d9360db2fd2c820f03ed77a8be35a4a12970e916cb508548d71`이다.

```sh
cargo build --locked --release --manifest-path tools/morph-compare/runner/Cargo.toml
jq -c '
  select(.query == "서다" or .query == "나다" or .query == "지다") |
  .id = (input_filename | split("/")[-1]) + ":" + .id
' negatives.jsonl positives.jsonl possibility-current-corrected.jsonl > "$focused"
scripts/benchmark-run.sh run --name particle-interior -- \
  python3 tools/morph-compare/measure-smart.py "$input" "$out" \
  --baseline "$baseline_runner" ef6fba64 "$lexicon" "$component" "$predicates" \
  --candidate "$candidate_runner" 752d1121 "$lexicon" "$component" "$predicates"
```

입력별 워밍업 1회 뒤 새 프로세스로 순서를 바꿔 가며 5회
측정했다. 단위와 대표값은 초기화·최근접 순위 p95의 ms,
처리량의 건/s, 최대 RSS의 KiB이며 중앙값 [최솟값, 최댓값]이다.

처리량·p95 변화는 고정 음성 +0.04%·−0.84%, 교정 GSD
+0.46%·−1.73%, 집중 입력 −1.31%·+1.05%였다. 집중 입력의
첫 비교에서도 처리량이 0.42% 낮았다. 같은 runner를 양쪽에
사용한 집중 입력 A/A 변화는 −0.13%·+2.50%였다. 집중
입력으로 확인한 처리량 감소의 크기는 두 측정에서 달랐다.

## WASM

`wasm-pack build crates/kfind-wasm --target bundler --out-dir "$out" --out-name kfind --release`로
기준선 `ef6fba64`과 후보 `752d1121`을 비교했다.
원본은 2,857,780 → 2,858,176 B (+396), gzip은
972,620 → 972,678 B (+58), Brotli는 716,197 → 716,963 B (+766)다.
Node 26.11.1에서 기본 Token과 full POS·component를 장착한
Smart·Any의 NFC·NFD 입력을 빌드마다 66건씩 대조했다.
Smart의 조사 내부 오반환 14범위가 제거됐다. 두 빌드의
Smart에서 NFD `서있었다` [26, 56)가 누락된다. 동일 문장의
NFC와 띄어 쓴 동사의 NFC·NFD는 기대 범위를 반환한다.
