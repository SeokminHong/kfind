# 공개 UD 입력의 Smart 채점

UD 2.18 원문에서 만든 [세 고정 입력](../../tools/morph-compare/README.md#gsdpud-고정-감사-입력)을
`03299e22`와 같은 제품 코드의 `boundary full-pos smart` runner로 실행했다.
[한과 대의 원문 표적 검토](2026-11-22-ud-han-dae-source.md)를 포함한 저장소 등록부로
채점했다. 원본 양성에서 집계한 표적 범위 누락은 교정 GSD의 계약 누락과 별개다.

| 입력 | 원본 TP, FP, TN, FN / precision, recall, F1 (%) | 계약 TP, FP, TN, FN / precision, recall, F1 (%) | 계약 검토 / 제외 |
| --- | --- | --- | ---: |
| GSD 원본 양성 9,335행 | 8,292, 0, 0, 1,043 / 100, 88.83, 94.08 | 8,292, 0, 0, 1,043 / 100, 88.83, 94.08 | 0 / 0 |
| 교정 GSD 양성 9,298행 | 9,290, 0, 0, 8 / 100, 99.91, 99.96 | 9,290, 0, 8, 0 / 100, 100, 100 | 8 / 0 |
| 고정 음성 53,308행 | 0, 3,227, 50,081, 0 / 0, —, 0 | 1,432, 1,704, 50,054, 0 / 45.66, 100, 62.70 | 1,551 / 118 |

채점기는 고정 입력 SHA-256과 runner의 프로필, 경계 모드, 결과의 ID와 순서를
확인한다. 기존 임시 채점과 고정 음성 행렬 및 계약 오탐 1,704개의 ID가
일치했다. `any` 출력과 행 구성이 다른 양성 출력을 의도적으로 전달했을 때,
채점기는 각각 모드와 행 순서 오류를 보고하고 결과를 출력하지 않았다.

계약 양성의 표적 범위가 구조화돼 있지 않은 행은 반환 유무로 집계한다.
초과 범위는 각 양성 행의 전체 반환 목록과 원문을 대조해 검증한다.
제품 실행 코드와 리소스는 동일해 기존 성능 측정을 사용한다.
