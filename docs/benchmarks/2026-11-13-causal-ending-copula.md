## 품질

GSD의 `있어서인가`, `있어서이다`, `되어서였다`에서 본용언 검색이 어절을
놓쳤습니다. 이유를 나타내는 `-아/어서` 뒤의 지정사 활용을 확인하고 어절 끝까지
반환하도록 했습니다. `늦어서이다`, `좁아서인가`, 두 어절인 `늦어서 이`를
대조했습니다. `있어서이다` 회귀의 `붉은빛`은 붙여 쓰고 범위를 다시 정렬했습니다.
[국립국어원 설명](https://m.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=334605) ·
[UD 회귀](../../data/fixtures/ud_morphology_cases.tsv)

행렬은 TP, FP, TN, FN 순서이며 비율은 precision, recall, F1 순서입니다. 회귀와 GSD
양성은 정확한 범위로, KAIST는 겹치는 범위로, 표적 범위가 없는 일반 음성은 반환 여부로

## 성능

Apple M1 Max arm64, macOS 26.6.2(25G83), Darwin 25.6.0, Rust·Cargo 1.97.0에서
동일한 리소스와 release 설정을 사용했습니다. 새 프로세스에서 입력별로 warm-up 1회 후
5회 측정하고 순서를 교대했습니다. 처리량은 runner 평가 시간, p95는 nearest-rank,
RSS는 `/usr/bin/time -l`의 최대 상주 메모리입니다. 셀은 중앙값 [최솟값, 최댓값]입니다.

양성 처리량은 1.69% 늘고 p95는 1.10% 줄었습니다. 음성 처리량은 0.64% 줄고 p95는
0.68% 늘었습니다. 초기화·RSS 중앙값 차이는 1.14% 이내였습니다.

```sh
cargo build --locked --release --manifest-path tools/morph-compare/runner/Cargo.toml
KFIND_FULL_POS_LEXICON="$full_pos_dir/lexicon.bin" \
KFIND_COMPONENT_RESOURCE="$component_resource" \
KFIND_ENRICHED_PREDICATES="$enriched_predicates" \
  /usr/bin/time -l "$runner" boundary full-pos smart "$input" "$output"
```
