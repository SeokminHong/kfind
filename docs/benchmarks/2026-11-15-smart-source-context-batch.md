# 합성 이동 용언과 인용된 어미

`가져갈`과 `데려갈`의 자모가 어간과 관형형 어미에 걸쳐 융합되므로,
음절 단위의 더 긴 어간 경로는 확인할 수 없다. 앞 용언의 연결형,
생성된 `가다` 활용, 어절 전체의 출처 동사·어미 분석이 모두 확인되면
앞 용언 검색에서 어절 전체를 반환한다.
[국립국어원 합성 이동 용언의 붙임](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=73&pageIndex=1&qna_seq=335135)

지정사 생략형 `-다`는 인용된 말 뒤에 붙을 수 있다. 여는 부호
뒤의 독립된 `다`는 제외하고, `“가”다`와 `"가"다`의 `다`는
계속 반환한다. 직선 따옴표는 왼쪽에 붙은 말이 있을 때 닫는 부호로
해석할 수 있다.
[국립국어원 인용 부호의 붙임](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=90&pageIndex=1&qna_seq=328362)

## 품질

고정 사전의 원본과 보정본, 교정 GSD, GSD·PUD 음성, 교정 KAIST dev와
계약 검토 KAIST test의 모든 결과를 ID 및 바이트 범위로 대조했다.
동사 질의에서 `갈`로 끝나는 어절이나 지정사 질의에서 여는 부호 뒤
`다`가 있는 행은 사전 원본·보정본 각각 9건, GSD 11건, 음성 104건,
dev 2건과 test 6건이다. 바뀐 고정 코퍼스 결과는 test의
`가지다 → 가져갈` 한 건이며 반환 범위는 58..67이다.
나머지 행렬은 [직전 기준선 보고서](2026-11-15-smart-nominal-context.md#품질)와 같다.
골드 925건과 walk/hang, workspace 테스트 634건, Clippy를 통과했다.

행렬은 TP, FP, TN, FN 순서이며 비율(%)은 precision, recall, F1 순서다.
KAIST는 표적과 겹치는 반환을 채점한다. 용언 대조는 열 가지 합성
활용과 네 가지 명사·다른 용언 표면의 정확한 범위를 채점했다.
용언·인용 대조의 계약 검토는 0건이다. 용언 대조 FP 1건은 명사
`해갈`에 해당한다.

| 입력 (Smart) | 버전 | Raw 행렬 / 비율 (%) | 보정 행렬 / 비율 (%) |
| --- | --- | --- | --- |
| 용언 대조 14건 | 기준선 | 8, 1, 3, 2 / 88.89, 80.00, 84.21 | 8, 1, 3, 2 / 88.89, 80.00, 84.21 |
| 용언 대조 14건 | 후보 | 10, 1, 3, 0 / 90.91, 100.00, 95.24 | 10, 1, 3, 0 / 90.91, 100.00, 95.24 |
| 인용 대조 6건 | 기준선 | 3, 3, 0, 0 / 50.00, 100.00, 66.67 | 3, 3, 0, 0 / 50.00, 100.00, 66.67 |
| 인용 대조 6건 | 후보 | 3, 0, 3, 0 / 100.00, 100.00, 100.00 | 3, 0, 3, 0 / 100.00, 100.00, 100.00 |
| 계약 검토 KAIST test 2,592건 | 기준선 | 1288, 2, 1294, 8 / 99.84, 99.38, 99.61 | 1290, 0, 1298, 1 / 100.00, 99.92, 99.96 |
| 계약 검토 KAIST test 2,592건 | 후보 | 1289, 2, 1294, 7 / 99.85, 99.46, 99.65 | 1291, 0, 1298, 0 / 100.00, 100.00, 100.00 |

교정 KAIST dev의 누락 2건은 `기술면`, `종교면` 표기다.
측면을 뜻하는 `면`을 띄어 쓴 대조 문장에서 각각 `기술`과
`면에서`를 반환한다. 고정 dev 집계에는 원래 입력과 정답을 사용했다.
[국립국어원 측면을 뜻하는 ‘면’의 띄어쓰기](https://www.korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=5563&mn_id=62&pageIndex=246)

## 성능

기준선 `b5cea187`과 후보 `1a680680`을 Apple M1 Max arm64,
macOS 26.6.2와 Rust/Cargo 1.97.0 release의 Full POS Smart로 비교했다.
워밍업 1회 후 새 프로세스로 5회씩 실행하고 버전 순서를 교대했다.
값은 중앙값 [최솟값, 최댓값]이며 p95는 최근접 순위, RSS는 최대 상주 메모리다.

| 입력 | 버전 | 초기화 ms | 처리량 cases/s | p95 ms | RSS MiB |
| --- | --- | --- | --- | --- | --- |
| KAIST test | 기준선 | 61.202 [60.702, 63.821] | 33567 [31392, 33695] | 0.07692 [0.07592, 0.08046] | 66.266 [66.156, 66.313] |
| KAIST test | 후보 | 61.458 [60.479, 62.859] | 33595 [28901, 33738] | 0.07671 [0.07604, 0.08604] | 66.516 [66.453, 66.875] |
| GSD | 기준선 | 60.864 [60.555, 63.264] | 30281 [29694, 31745] | 0.07233 [0.06875, 0.07383] | 80.781 [80.641, 81.047] |
| GSD | 후보 | 60.798 [60.374, 61.579] | 31584 [30762, 31988] | 0.06892 [0.06817, 0.07096] | 80.938 [80.813, 80.969] |
| 음성 | 기준선 | 61.319 [61.279, 61.689] | 20227 [19849, 20321] | 0.12383 [0.12296, 0.12762] | 127.281 [127.125, 127.328] |
| 음성 | 후보 | 61.840 [60.631, 62.777] | 20057 [20013, 20290] | 0.12500 [0.12296, 0.12608] | 127.625 [127.547, 128.266] |

test·GSD·음성 처리량은 각각 +0.08%, +4.30%, −0.84%이며
p95는 −0.27%, −4.72%, +0.94%다. 처리량과 p95는 측정 범위가
겹친다. RSS 중앙값은 각각 +0.38%, +0.19%, +0.27%이며
test와 음성의 RSS 측정 범위는 떨어져 있다.
