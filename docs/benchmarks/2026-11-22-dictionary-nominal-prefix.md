# 표준국어대사전의 대- 결합 명사

표준국어대사전의 직접 구성 성분 표기를 사용해 `대학교`, `대법원`,
`대용량` 같은 명사의 첫 성분을 접두사로 판정한다. 고정 사전에서
붙여 쓴 동형 표제어가 모두 `대-`로 분절되는 `大`·`對` 계열 명사
429개를 추출했다. `대프랑스`는 사전의 `대프랑스 동맹`과 접두사
`대-(對)`에 근거한다. `대나무`의 명사 성분과 `차 두 대가`의 단위 명사는
고정 회귀에서 바이트 범위를 확인했다.
[표준국어대사전 붙임표 설명](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?qna_seq=335713) ·
[표준국어대사전 대-(對)](https://stdict.korean.go.kr/search/searchView.do?word_no=79514) ·
[표준국어대사전 대프랑스 동맹](https://stdict.korean.go.kr/search/searchView.do?word_no=412086)

UD 2.18 GSD·PUD test에서 어절 첫머리가 확인된 결합 명사인
표면 20곳을 검토했다. 명사 `대` 질의의 오반환 14곳이 NFC·NFD에서
같이 제거됐다. 사전 목록 전체의 기본형·주격 결합형·지정사 결합형
1,287개에서 기준선이 반환한 첫 성분 1,197곳을 제거했다.
`대지구대` 계열에 남은 마지막 음절 3곳은 별도의 접미사 판정 대상이다.

고정 12세트의 Smart·Token·Any 반환 목록 249,243개 중 Smart 음성
11건이 달라졌다. 교정 GSD 9,298행의 전체 반환 범위는 같았다.

## 네이티브 형태 판정

`82d130fb`와 `deb2b45e`의 release runner를 Apple M1 Max, 32 GiB,
macOS 26.6.2 (25G83), Rust·Cargo 1.97.0, Python 3.14.8에서
[교대 측정 명령](../../tools/morph-compare/README.md#smart-기준선과-후보-성능-비교)으로
비교했다. 고정 입력과 리소스 체크섬은
[앞선 비교](2026-11-22-pronoun-before-cause.md#네이티브-형태-판정)와 같다.
각 입력의 측정군별 새 프로세스로 워밍업 1회, 교대 측정 5회를 실행했다.
표의 값은 중앙값 [최솟값, 최댓값]이다.

사전 입력은 [추출 도구](../../tools/nikl-lexicon/README.md#어휘-항목-audit)의
TSV를 사전순으로 읽어 각 표제어의 기본형, 주격 결합형, 지정사 결합형을
이 순서로 작성한다. 1부터 시작하는 번호를 `stdict-prefix:`에 붙인 ID와
`query="대"`, `pos="noun"`, `expected=false`를 사용한다.
JSONL SHA-256은 `2117547f68e10f187c77167b1a2ab4d024873f3a20e8a965402660adcb24bcfe`다.
같은 명사 질의를 반복하므로 전체 형태 판정과 분리해 해석한다.

## 공통 component의 접두사 분절 실험

기존 compact component를 디코딩했을 때 사전 표제어 429개 중 425개의 전체
표면형이 있었고, 첫 성분이 `XPN`인 분석은 0개였다. `대` 자체에는 접두사,
명사와 단위 명사 분석이 함께 있다. 전체 표면형 등재와 첫 음절만으로는
`대학교`의 접두사와 `대나무`의 명사 성분을 구별할 수 없다.

`087a68ed`의 제품 판정을 기준으로, 기존 component 형식에 사전에서 분절을
확인한 `대-` 429개와 독립 대조어 `정사각형`을 추가했다. 접두사 범위를
`XPN`, 나머지 어근을 `XR`로 표시했다. 나머지 어근의 내부 구조나 품사는
이 표기에서 추론하지 않는다. 기존 `kfind-data-build-component`가 고정
MeCab-Ko 사전과 추가 CSV를 함께 읽는다. 런타임에서는 기존 component
조회로 명사 후보와 `XPN`의 시작과 끝이 일치하는지 확인하고, 남은 조사나
지정사까지 검사한다. 추가 CSV SHA-256은
`65670555b2f139d35e15d41c780cead68342ce309e20e3aaff707c963b6a5ad4`다.
기존 component SHA-256은
`8928bce4a6d57ed85ef0d0243240c0735d84bf68db737ac6935dde2eb3757e30`,
실험 component SHA-256은
`7700fbed3b4293a558ac186c8bb28239d9e23c9f5429f0f6ff558ccc9a69a30e`다.

실험 component를 장착한 실행에서 고정 12세트의 Smart·Token·Any와 교정 GSD
Smart의 전체 반환 목록 258,541개가 기준선과 일치했다. 고정 음성의 위 혼동
행렬과 품질 지표도 후보 행과 같다. 별도 WASM 대조 19개에서
`new Kfind(component)`와 `Kfind.withResources({component, fullPos, enrichedPredicates})`는
모두 `대나무`·`대숲`·`대밭`과 `차 두 대가`의 반환을 보존했다.
`대노잼`과 `대꿀잼`은 두 버전 모두 반환하지 않았고, `대실패도 있었다`의
첫 음절 오탐은 두 버전 모두 남았다. 새로운 표면형에 적용할 생산적 결합
규칙의 근거는 이 실험에서 확인하지 못했다.

`new Kfind()`의 Any·Token 반환은 대조 19개에서 같았고, 품사를 지정한
Smart는 두 버전 모두 component 필요 오류를 반환했다. 기존 component를
실험 WASM에 장착했을 때 19개 중 9개에서 제품이 제거한 첫 음절 오탐이
다시 발생했다. 기존 리소스를 장착하는 소비자에서도 이 판정을 유지할 수
있어야 공통 component로 전환할 수 있다.

`wasm-pack 0.15.0`의 `wasm-pack build crates/kfind-wasm --target bundler --release --locked`로
같은 환경에서 빌드했다. Node 26.11.1의 `gzipSync` 레벨 9와
`brotliCompressSync` 기본 설정으로 WASM 바이너리만 압축했다. 단위는 바이트다.
