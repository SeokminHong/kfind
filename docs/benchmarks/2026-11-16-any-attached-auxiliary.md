# Any의 연결형 뒤 붙여 쓴 보조 용언

`-아/-어` 연결형 끝에서 보조 용언이 완결되고 compact 리소스에서
해당 어절 구조가 확인될 때 반환 범위를 넓힌다. 본용언의 연결형은
기존 활용 경로, 보조 용언은 사전 결합 조건과 기존 활용 검증을 사용한다.
`알려줘`, `고쳐주신다`, `열려있다`를 확인하고 `찾아 줘`의 어절 경계와
`거뒀기`의 동형 분절을 대조했다.

## 품질

고정 입력 12세트를 Smart·Any·Token으로 실행해 249,243행의 입력 ID,
리소스 체크섬과 전체 UTF-8 반환 범위를 대조했다. 리소스가 있는 Any
53행만 달라졌다. 리소스 없이 실행한 Any와 두 다른 모드의 범위는
기준선과 같았다. 사전 원본 진단을 제외한 고정 평가 11세트의
Smart 계약 FN은 모두 0건이었다.

첫 후보는 같은 어절의 어느 위치에서든 보조 용언 경로가 성립하면
확장할 수 있었다. 이 조건은 `듣다 → 들어가면`과 같은 음성 31행의
기존 오탐 범위를 넓혔다. 어절 첫 본용언의 연결형에 맞춰 보조 용언
활용을 확인하고 경쟁 체언·용언 구조를 검토한 후보에서 해당 확장이
모두 사라졌다. 고정 음성 53,308행과 hard negative 45행은 반환 범위
변경이 0건이다. PUD의 `타버렸고`는 원본에서 `타`만 정답으로
표시됐으며 기존 계약 검토에는 붙여 쓴 보조 용언까지의 범위가 등록돼
있다. 이번 비교에서 원본 정답과 계약 검토를 그대로 사용했다.

행렬은 TP, FP, TN, FN 순이고 비율(%)은 precision, recall, F1 순이다.
GSD와 사전 원본에 적용한 별도 계약 검토는 0건, PUD는 6건,
고정 음성은 171건이다.

Rust 포맷, Clippy를 통과했다. CLI의 canonical 모드에서 NFD
`알려줘`의 반환 범위가 원문 UTF-8 0..21인 것도 확인했다.

## 재현

CLI stdin은 교정 GSD에서 문장 중복을 첫 등장 순서로 제거한 961줄
99,733바이트이며 SHA-256은
`207ca80886c6856ca8e372c5bd96aa8decb2f6c00ab70643438cf9e3f0d6f45d`다.
[고정 GSD·음성·사전 입력](2026-11-16-any-noun-before-copula.md#재현)과
같은 lexicon·enriched 파일을 사용했다. compact의 SHA-256은
`da0cb23a2f85941932a7c431d2a8446563a49c48e8215dac2dd7e1a790a0eb5c`다.
compact가 없는 CLI 검증에는 나머지 파일이 같은 데이터 디렉터리를 썼다.

```sh
cargo build --release --locked --manifest-path tools/morph-compare/runner/Cargo.toml --target-dir "$runner_build"
cargo build --release --locked -p kfind-cli --target-dir "$cli_build"
KFIND_FULL_POS_LEXICON="$data/lexicon.bin" KFIND_COMPONENT_RESOURCE="$data/morphology-component-compact.kfc" KFIND_ENRICHED_PREDICATES="$data/predicates.enriched.tsv" \
  /usr/bin/time -l "$runner_build/release/morph-benchmark-runner" boundary full-pos any "$input" "$output"
/usr/bin/time -l "$cli_build/release/kfind" --data-dir "$data" --boundary any --pos verb --json "$query" - < "$gsd_text"
```
