# 부사·형용사 연결형과 체언 경계

Smart는 어절 전체의 부사 또는 형용사 연결형 분석과 어절 앞의 체언 분석이
경쟁할 때, 체언 쪽에 실제로 소비한 조사나 사전 성분 정렬이 있는지 확인한다.
`그래도`의 `그`와 `저래도`의 `저`를 제거하고 `그가`, `저라도`의
조사 결합, `그래도`의 부사 및 `그렇다` 활용은 유지했다.

## 품질

[앞선 비교와 같은 12개 입력](2026-11-15-joined-adverb-connective.md#품질)의
Smart·Any·Token 249,243행을 ID, 리소스 해시, 반환 바이트 범위로 대조했다.
KAIST 품사 미지정 test에서 `그래도`의 반환 한 건이 사라졌다.
GSD·PUD 음성에서 `물론`, `매우`, `앞서`, `저래도`와 같은 판정 경로의
표면형을 대조했다. 고정 음성에서 실제로 바뀐 표면형은 14종, 행은 46건이다.
44행에서 반환이 사라졌고 두 행에서는 다른 반환이 유지됐다. KAIST 품사 지정
dev와 그 표본의 같은 원문에서는 `물론`의 불필요한 `물`만 사라지고 정답
`물줄기는`에 겹치는 반환이 유지됐다. 다른 입력과 Any·Token 반환은 동일했다.

품사 미지정 test의 원본 FN 4건과 별도 1,000건 표본의 원본 FN 2건은
비표준 붙여쓰기가 목표 어절에 영향을 준 사례다. 동일 원문에 대한 기존 심사와
표준 표기를 확인했고, 원본 입력과 레이블을 보존했다. 새 검토의 네 표준
대조문은 모두 Smart에서 반환됐다. Test의 음성 두 건은 주격 조사 `이`와
사전이 확인한 `보다`의 파생형 `보이고`가 실제 질의 대상이다.
아래 계약 검토는 양쪽 실행 결과에 동일하게 적용했다. Test 6건, 표본 2건,
GSD·PUD 음성 57건을 원문 SHA-256·ID·질의·품사·레이블로 확인했다.

행렬은 TP, FP, TN, FN 순서다. 비율(%)은 precision, recall, F1 순서다.
KAIST 양성은 골드 범위와 겹침, 음성은 반환 여부로 채점한다.
GSD·PUD 음성은 반환 여부로 채점한다.

## 성능

Apple M1 Max arm64, macOS 26.6.2, Rust/Cargo 1.97.0 release,
Full POS Smart에서 기준선 `ff076ac6`과 후보 `b3158ce8`을 비교했다.
기준선 실행 파일의 빌드 소스 `01e47e64`는 이후 문서·계약 검토를
추가한 `ff076ac6`과 런타임·리소스가 같다. 워밍업 1회 뒤 새 프로세스로
5회씩 실행하고 순서를 교대했다. 표는 중앙값 [최솟값, 최댓값]이다.
p95는 최근접 순위, RSS는 최대 상주 메모리다.

KAIST, 교정 GSD, 음성 순으로 처리량 중앙값은 +3.27%, +1.12%, +0.06%,
p95는 −1.87%, −0.82%, +0.47%다. 세 입력에서 처리량과 p95 범위가
각각 겹쳤다.

## 재현

```sh
cargo build --release --locked --manifest-path tools/morph-compare/runner/Cargo.toml
scripts/benchmark-run.sh run --name kaist-nominal-prefix -- \
  /usr/bin/time -l "$runner" "$evaluator" full-pos smart "$input" "$output"
```

`evaluator`는 KAIST 품사 미지정에서 `untagged`, 교정 GSD와 고정 음성에서
`boundary`다. [KAIST 입력 SHA-256](2026-11-15-automatic-predicate-and-quantity.md#재현),
[GSD·PUD 입력 SHA-256](2026-11-15-joined-predicate-chain.md#재현),
[Full POS 리소스](2026-11-15-smart-source-context-batch.md#재현)는 앞선 비교와 같다.
