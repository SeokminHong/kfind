# 사전에 정렬된 명사 접미사의 검색 범위

`지명자는`의 `자`에는 사전에 정렬된 접미사 분석이 있다. Smart는
접미사로 끝나는 명사와 조사가 어절을 완성하는 경우에도 같은
위치의 추론 명사를 반환했다. 사전에 끝 성분이 접미사로 정렬되고
전체 명사가 단독으로 또는 조사·지정사와 결합해 어절을 완성하면
해당 성분에 접미사 품사를 적용한다. 같은 위치의 사전 명사 분절이
어절을 완성하면 그 명사 범위는 유지한다.
[접미사 분절의 출처와 입력](2026-11-23-person-suffix-component.md)

고정 음성에서 명사 `자` 질의 182행을 점검했다. 기준선의 잔여 여덟
행은 모두 원문으로 확인했다. `합격자 비율`, `지명자는`,
`경제학자들은`, `유권자의`, `지도자들은`의 내부 범위 다섯 개가
해소됐다. 사전에 정렬된 해당 접미사 분석이 없는 `전자`, `자니`,
`제3자`의 반환은 남았다.

여덟 문장의 관련 질의 311개를 원문과 맞춤법 검토문에 각각
실행했다. 아래 네 문장의 표기를 교정했다. 원문과 교정문에서
동일한 다섯 범위가 사라졌고 남은 세 범위도 양쪽 입력에 있었다.

## 네이티브 형태 판정

Apple M1 Max 32 GiB, macOS 26.6.2 arm64, Rust·Cargo 1.97.0,
Python 3.14.8에서 기준선 `1f37ead6`과 후보 `9723db1d`의 release
러너를 비교했다. 같은 사전 리소스와 고정 음성·등록 교정 GSD
입력을 사용했다. 각 조건을 한 번 가동한 뒤 교대 순서로 새
프로세스 5회를 측정했다. 지연 시간은 실행별 최근접 순위 p95다.
표는 중앙값 [최솟값, 최댓값]이다.
[입력·사전 체크섬](2026-11-23-person-suffix-component.md#네이티브-형태-판정)

기준선 러너 SHA-256은
`37c9053e3c12dbbc24a30a1a4ded3ff4dcd5155212700a5cfdbff519a9e183ac`,
후보는 `0f0e201d99e8cc3ee0c0548a3881ea05ac1d7eb1c415e797b6d2e97bd8ad291b`다.

| 입력 | 실행 | 초기화 ms | 처리량 cases/s | p95 ms | 최대 RSS KiB |
| --- | --- | --- | --- | --- | --- |
| 고정 음성 | 기준선 | 62.005 [61.872, 62.589] | 19,599.5 [19,206.6, 19,943.4] | 0.1266 [0.1232, 0.1284] | 130,928 [130,688, 131,296] |
| 고정 음성 | 후보 | 61.977 [61.841, 62.614] | 19,646.4 [19,464.9, 19,839.1] | 0.1266 [0.1248, 0.1271] | 131,072 [130,880, 131,200] |
| 등록 교정 GSD | 기준선 | 61.160 [61.095, 61.411] | 30,181.8 [29,532.7, 30,288.2] | 0.0717 [0.0712, 0.0730] | 83,472 [83,376, 83,568] |
| 등록 교정 GSD | 후보 | 61.351 [61.204, 62.492] | 30,249.9 [29,061.9, 30,314.6] | 0.0717 [0.0715, 0.0801] | 83,456 [83,440, 83,488] |

처리량 중앙값은 고정 음성에서 +0.24%, 등록 교정 GSD에서 +0.23%였다.
p95 중앙값은 각각 같았다. 이 차이는 앞선 동일 러너 반복에서
관측한 변동보다 작아 성능 회귀 판정을 유보했다.

```sh
cargo build --locked --release --manifest-path tools/morph-compare/runner/Cargo.toml
scripts/benchmark-run.sh run --name aligned-suffix -- \
  python3 tools/morph-compare/measure-smart.py "$input" "$out" \
  --baseline "$baseline" 1f37ead6 "$lexicon" "$component" "$predicates" \
  --candidate "$candidate" 9723db1d "$lexicon" "$component" "$predicates"
```

## WebAssembly

같은 리비전을 wasm-pack 0.15.0의 release bundler로 빌드했다.
압축에는 `gzip -9nc`와 `brotli -q 11 -c`를 사용했다.

| 리비전 | 원본 바이트 | gzip 바이트 | Brotli 바이트 |
| --- | ---: | ---: | ---: |
| `1f37ead6` | 2,834,447 | 962,080 | 708,185 |
| `9723db1d` | 2,836,074 | 962,828 | 708,723 |
| 증감 | +1,627 | +748 | +538 |

Node 26.11.1에서 두 빌드가 component 없는 Smart 명사 질의를
같은 오류로 거절하는지 확인했다. 같은 component를 장착한
API의 네 질의에서 정확한 범위를 확인했다. JavaScript에서 받은
UTF-16 위치를 원문의 UTF-8 위치로 환산해 비교했다.

```sh
wasm-pack build crates/kfind-wasm --target bundler --out-dir "$out" --out-name kfind --release
```
