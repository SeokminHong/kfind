# 구조 문맥 캐시의 준비 경계

기준선 `e9b4ee91`과 후보 `493a8aa8`을 비교했다. 기준선 runner는
Rust 소스와 리소스가 동일한 `dbcb89b1` 빌드를 재사용했다.
사전·교정 GSD·고정 음성 67,064건과 문맥 대조 78건의 결과 ID와 반환
바이트 범위가 일치했다. matcher·testkit 테스트 170개와 `verify-gold`도 통과했다.

여섯 입력의 원문, 계약 검토, 검색 결과가
[후보 수용 정책 분리 보고서](2026-11-14-morph-candidate-policy.md#품질)와 일치한다.
양쪽의 raw 및 계약 보정 행렬, precision, recall, F1은 그 표와 같다.

## 성능

Apple M1 Max arm64, macOS 26.6.2(Darwin 25.6.0), Rust/Cargo 1.97.0
release에서 full POS `smart`를 비교했다. 입력마다 양쪽을 한 번 워밍업한
뒤 새 프로세스로 5회씩 순서를 교대했다. 처리량은 평가 시간 기준이며
p95는 nearest rank다.

각 값은 중앙값 [최솟값, 최댓값]이다. 첫 측정의 교정 GSD 중앙값 변화를

처리량과 p95의 관측 범위는 두 세트 모두 각 입력에서 겹쳤다. 교정 GSD의
중앙값 변화 방향은 세트마다 달랐다.

```sh
cargo build --release --locked --manifest-path tools/morph-compare/runner/Cargo.toml
/usr/bin/time -l "$runner" boundary full-pos smart "$input" "$output"
```
