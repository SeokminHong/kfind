# 부정 보조 용언의 품사

`-지 않다`와 `-지 못하다`의 보조 동사·보조 형용사는
앞 용언의 품사를 따른다. 앞 용언의 완결된 연결형과 보조사,
`-진/-질` 준말을 확인한다. 동작 명사에 붙는 피동 접미사
`-되-`와, 같은 절에서 목적어를 취하는 동사도 판정에 사용한다.
`적지 않은 피해`는 수량을 나타내는 형용사와 글로 기록하는 동사의
두 관형절이 가능하므로 양쪽을 유지한다.
[국립국어원 부정 보조 용언](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=73&pageIndex=1&qna_seq=334688)
· [한국어기초사전 -되다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=74902)
· [한국어기초사전 입다](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=17174)

## 품질

Smart full-pos 기준선 `8d463f35`과 후보 `2be95cad`를 동일한
입력과 정답 범위로 비교했다. 원문과 교정 GSD에서 `않다`,
`못하다`, `말다` 질의 54행씩과 별도 대조 35행을 확인했다.
고정 음성에 든 유일한 해당 표제어는 `말다` 444행이며 반환
범위가 같다. 고정 회귀는 짧은 연결형과 완결 어미, 단독 동사,
목적어가 있는 절과 품사 경쟁을 대조한다.
[입력과 리소스 체크섬](2026-11-23-gsd-standalone-noun-spacing-review.md#평가)

교정 s468:44의 형용사 질의는 피동 동사 뒤 `않고 [297, 303)`의
오탐을 제거하고 `않을 [365, 371)`을 보존한다. s760:13의
형용사 질의는 `부상을 입지` 뒤 `않았으나 [44, 56)`의 오탐을
제거하고 `않은 [99, 105)`을 보존한다. s468의 `무관치 않을`은
보조 형용사로 확인했으며, 같은 문장의 동사 질의에 반환되는
오탐은 원문과 교정문 평가에 남아 있다.

원문 s53:16, s235:15, s336:4, s940:4는 GSD의 동사 태그와 달리
앞말이 각각 형용사 `아무렇다`, `부드럽다`, `많다`, `많다`다.
원래 주석은 보존하고 계약 채점에 품사 검토를 반영했다.
`고생했었든데 → 고생했었는데`, `일년 → 일 년` 등
교정 예문과 문장 전체를 대조했다. 보조 용언 품사를 검토한
원문·교정문에 동사와 형용사를 각각 질의한 44행에서 같은
범위 변화를 확인했다. 대조 입력의 SHA-256은
`7c5dcd8915dfff5b2e61e8a75b8d43f587f126edc3b0ad1f95b7d23418c9a63e`다.

s14:3의 `충실하지`, s353:10의 추측 표현 `것 같진`, s638:2의
`맵지도`도 사전에서 형용사 문형으로 확인했다. 해당 동사
오탐은 두 빌드에서 발생한다. s976:4의 `달지 않고`는
형용사와 동사 해석의 문장 내 경쟁을 더 검토해야 한다.
[한국어기초사전 충실하다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=79531)
· [한국어기초사전 같다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62076)
· [한국어기초사전 맵다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=74131)

기존 범위 258,541행을 비교한 결과 교정 GSD 두 사례를 각각
기록한 두 실행과 구형 어미 진단 세 행에서 반환이 달라졌다.
진단 세 행의 `많지 않거들랑`, `아무렇지도 않은걸`,
`만족스럽지 않을지라도`는 사전 용례와 맞는 표기다. 형용사
질의에서는 양쪽 빌드가 세 어미까지의 전체 범위를 반환한다.
구형 진단에서는 이 세 행에 동사 품사를 부여했다.

## 성능

Apple M1 Max 32 GB, macOS 26.6.2 arm64, Rust 1.97.0,
Python 3.14.8에서 두 release 빌드를 같은 입력과 리소스로
실행했다. 빌드마다 워밍업 1회 뒤 새 프로세스에서 순서를
교대해 5회 측정했다. 실행별 p95는 최근접 순위로 계산했다.

```sh
cargo build --locked --release --manifest-path tools/morph-compare/runner/Cargo.toml
scripts/benchmark-run.sh run --name "negative-auxiliary-pos-$workload" -- \
  python3 tools/morph-compare/measure-smart.py "$input" "$out" \
  --baseline "$baseline_runner" 8d463f35 "$lexicon" "$component" "$predicates" \
  --candidate "$candidate_runner" 2be95cad "$lexicon" "$component" "$predicates"
```
