# 동일한 GSD 원문의 검토 범위 재사용

원문 GSD와 등록 교정 GSD 사이에서 문장 바이트, 질의, 지정
품사가 같은 경우 다른 입력에서 검토한 양성 범위를 추가 반환의
근거로 사용한다. 현재 행의 적중과 전체 정답 범위는 해당 입력의
주석과 검토를 따른다. 다른 위치의 추가 반환과 판정 대기 범위는
남는다. 사전 검토 레지스트리에 기록된 문장 해시도 확인한다.

## 평가 결과

같은 Smart full-pos 실행 결과를 기준선과 후보 채점기에 각각
입력했다. 교정 GSD의 미판정은 115행 121범위에서 107행
113범위로 줄었다. 재사용한 범위는 `4분기`, 학교명 안의
`고등학교`, `대한변호사협회`의 `변호사`, `준우승`의 `우승`
두 행, `위원회`의 `위원`, `특수 목적고`의 `목적` 두 행이다.
각 범위는 원문 검토에 있고 등록 교정문의 해당 문장 바이트와
일치한다. [범위 검토 원본](../../tools/morph-compare/contract-contrast-evidence.jsonl)

| 입력 | 원본 TP, FP, TN, FN / precision, recall, F1 (%) | 계약 TP, FP, TN, FN / precision, recall, F1 (%) | FPc | FNc |
| --- | --- | --- | ---: | ---: |
| 고정 음성 양쪽 | 0, 3,038, 50,270, 0 / 0, 0, 0 | 1,426, 1,498, 50,236, 0 / 48.77, 100, 65.56 | 1,499 | 0 |
| 원문 GSD 양쪽 | 8,229, 0, 0, 1,106 / 100, 88.15, 93.70 | 8,639, 6, 78, 609 / 99.93, 93.41, 96.56 | 13 | 609 |
| 교정 GSD 양쪽 | 9,286, 0, 0, 12 / 100, 99.87, 99.94 | 9,285, 2, 11, 0 / 99.98, 100, 99.99 | 3 | 0 |

원문 GSD의 추가 반환 미판정은 575행 637범위다. 고정 음성의
계약 양성 1,207행은 전체 정답 범위 검토가 필요하고 제외 42행의
37범위도 판정이 남아 있다. 회귀 테스트는 문장·질의·품사 변경,
현재 정답 누락과 현재 검토 범위에 없는 추가 반환을 각각 확인한다.

## 채점기 성능

Apple M1 Max 32 GB, macOS 26.6.2 arm64와 Python 3.14.8에서
`c2483d1e`와 `bf61b632`의 채점기를 비교했다. 파일별로
워밍업 1회 뒤 버전 순서를 교대하며 새 프로세스 5회를 실행했다.
초시계에는 프로세스 시작, 입력 읽기, 검증과 JSON 출력이
포함된다. 최대 RSS는 `/usr/bin/time -l`을 사용했다.
아래 명령에서 `$revision`으로 소스를 추출하고 두 버전에 같은
평가 입력과 실행 결과를 전달한다.

```sh
git show "$revision:tools/morph-compare/score-ud-audit.py" > "$scorer_source"
/usr/bin/time -l python3 -c '
import sys
from pathlib import Path
script = Path(sys.argv[1])
sys.argv = [str(script), *sys.argv[2:]]
sys.path.insert(0, str(script.parent))
exec(compile(sys.stdin.buffer.read(), str(script), "exec"),
     {"__file__": str(script), "__name__": "__main__"})
' "$PWD/tools/morph-compare/score-ud-audit.py" --residual "$fixture" "$runner_output" \
  < "$scorer_source" > /dev/null
```
