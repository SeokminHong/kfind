# 검색 계약과 문서 진입 구조

## 판단 근거

검토 기준은 bb44a8db6495781b23dff454a3574df102ac7ec8이다. Native CLI와 npm CLI는
질의 엔진을 공유하지만 파일 순회·리소스·입력 적재·출력 단위·좌표계가 다르다.
설치 안내에서 이를 구분하지 않으면 같은 명령 이름을 출력 호환성으로 오해할 수 있다.

`crates/kfind-matcher/src/morph/context.rs`는 window 추출과 context 준비 실패를
`Option`으로 전달한다. `morph.rs`는 context가 없으면 후보를 거부한다.
`kfind-search::SearchSummary`에는 판정 불가 집계가 없다. 이 판단은 코드 경로를
확인한 결과이며, 특정 긴 입력에서 실제 누락을 재현한 품질 측정은 아니다.

`agent_hook.rs`와 에이전트 통합 사양은 정확한 표면형 검색까지 포함한 한글 패턴의
`rg`, `grep`, `git grep` 차단을 규정한다. 경고 기본값으로 바꾸는 일은 문구 수정이
아니라 기존 통합 정책의 변경이다.

## 문서 구조

처음 방문한 사용자의 과제는 실행 환경 선택, 첫 검색, 결과 해석이다. 입력은 설치
환경과 짧은 질의이며, 확인할 결과는 원문 위치와 다음 점검 단계다. 내부 구조와
세부 명세는 기본 검색을 마친 뒤 필요한 문서로 연결한다.

홈에는 실행 예시와 목적별 링크를 둔다. 설치 페이지는 명령보다 먼저 호환성 표를
제시한다. 첫 검색은 설치 직후 결과를 확인하고 npm·고급 질의·자동화로 이어진다.
모바일도 같은 순서를 유지하며 메뉴를 열지 않아도 본문의 링크로 이동할 수 있다.
언어·버전 선택은 공통 header에 유지하고 기존 URL과 fragment를 보존한다.

결과 없음 안내는 오류, 검색 대상, 질의·품사·경계 조건을 차례로 점검하도록 한다.
내부 resolver의 `Unavailable` 상태가 일반 CLI의 진단 계약으로 노출된 것처럼
설명하지 않는다. Benchmark는 표준문과 오류 문장, 품질과 실행 시간을 분리해 읽는다.

## 후속 설계 범위

- 판정 불가 노출은 후보의 식별·중복 집계 기준, cache 재사용, 병렬 검색 요약,
  native·WASM API 호환성과 엄격 모드의 종료 계약을 함께 정해야 한다. 먼저 raw byte,
  정규화 scalar와 graph 상한을 각각 넘는 최소 재현을 만들고 기존 matcher 성능과 비교한다.
- Hook의 권고·강제 선택은 기본값과 기존 설치의 갱신 정책을 확정한 뒤 구현한다.
  문서는 현재 차단 범위와 직접 호출·통합 해제를 설명한다.
- 실제 문서 평가는 새로운 저장소·고정 질의·양성·음성 span을 사전 확정하고 개발용
  반례와 blind 평가를 분리한다. `smart`·`any`의 raw와 contract-adjusted 품질을 함께 보고한다.
- 구조 모듈 분리는 공유 graph 사실과 언어별 판정의 의존 관계를 먼저 그린다.
  파일 길이만을 이유로 나누지 않으며, 사양 분할은 기존 절 링크의 이전 계획과 함께 다룬다.

이 항목들은 문서 개편만으로 해결된 것으로 취급하지 않는다.
