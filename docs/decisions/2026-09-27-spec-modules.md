# 기술 사양의 분야별 파일 구성

## 판단 근거

분할 기준은 `9d2381cd70485e831d8fd2ef1ab8dab02dac8ca8`이다. 한 파일에 질의 문법,
형태 검색, 데이터, CLI, 바인딩, 배포와 검증 계약이 함께 있어 서로 다른 기능 변경이 같은
문서에서 충돌한다. 제품 동작과 규범의 우선순위는 바꾸지 않고 관련 절을 함께 읽을 수 있도록
파일을 나눈다.

## 선택

`specs/kfind.md`는 제품 목적, 아키텍처와 분야별 사양의 색인이다. 질의 언어, 형태 검색,
리소스, CLI, 바인딩, 배포, 검증은 같은 `specs/` 디렉터리의 분야별 파일에 둔다. 각 분야의
`0.x` 제품 계약은 그 파일의 뒤쪽 일반 설명보다 우선한다.

기존 절 번호와 제목은 색인에 남겨 fragment 링크의 도착 지점을 유지한다. 옮긴 본문은 한
파일에만 보관하고, 다른 분야의 절을 언급할 때는 해당 파일로 연결한다. 이후 기능 변경은
관련 분야의 사양부터 갱신한다.
